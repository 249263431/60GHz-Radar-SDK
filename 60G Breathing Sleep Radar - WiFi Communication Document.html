1. Description

This document mainly describes the MQTT protocol format for the 60G breathing and heartbeat radar device, helping users to obtain and set radar data for development convenience. Data content is transmitted in JSON format.

There are 2 topics for the 60G radar, as follows:

  • (1) Topic: /Radar60SP/DeviceID/sys/property/post – Reporting topic, through which the radar device reports data and setting response messages.
  • (2) Topic: /Radar60SP/DeviceID/sys/property/set – Sending topic, through which clients publish messages to the radar device.

2. Radar Functional Attributes

Online/Offline (online)

Active reporting. Attribute status: 0 (offline), 1 (online). Status changes are actively reported.

{
    "version": "1.0",
    "method": "post",
    "params": {
        "online": "0"   // device offline
    }
}

Initialization Complete (initFinish)

No active reporting. Data range: 0 (initialization incomplete), 1 (initialization complete). Supports query.

// Query format:
{
    "version": "1.0",
    "method": "get",
    "params": {
        "initFinish": "?"
    }
}

// Response format:
{
    "version": "1.0",
    "opt": "get",
    "res": "success",   // "fail" on failure, "success" on success
    "params": {
        "initFinish": "XXXX"
    }
}

3. Restricted Functional Attribute Reporting

This function mainly targets frequently reported attributes. Prohibit or allow reporting. Value 1 = prohibit reporting, 0 = allow reporting. Use method limit_set or limit_get. Multiple attributes can be set together.

// Query prohibited attributes:
{
    "version": "1.0",
    "method": "limit_get",
    "params": {
        "workDuration": "?",
        "locationOutOfBounds": "?",
        "someoneExists": "?",
        "motionStatus": "?",
        "movementSigns": "?",
        "humanDistance": "?",
        "humanPosition": "?",
        "heartBeat": "?"
    }
}

// Response:
{
    "version": "1.0",
    "opt": "limit_get",
    "res": "success",
    "params": {
        "workDuration": "0",
        "locationOutOfBounds": "0",
        "someoneExists": "0",
        "motionStatus": "0",
        "movementSigns": "0",
        "humanDistance": "0",
        "humanPosition": "0"
    }
}

// Set prohibited attributes:
{
    "version": "1.0",
    "method": "limit_set",
    "params": {
        "workDuration": "1",
        "locationOutOfBounds": "0",
        "someoneExists": "0",
        "motionStatus": "0",
        "movementSigns": "0",
        "humanDistance": "0",

// Set response:

5. OTA Upgrade

Upgrade Module (otaModule)

This attribute requires sending a command to distinguish which module to upgrade. 0 = WiFi module, 1 = radar module, default 0. Send this control command before each OTA upgrade.

{
    "version": "1.0",
    "method": "ota set",
    "params": {
        "module": "0"
    }
}

Upgrade Information (otaInform)

Sends upgrade information including firmware address and port number. The device receives this data, obtains the upgrade firmware from the specified URL and port, then starts upgrading. Returns failure on failure; on success, module restarts and reports the upgraded version number. Customer needs to build a web server.

{
    "version": "1.0",
    "method": "ota set",
    "params": {
        "otaInform": {
            "firmwareUrl": "http://192.168.31.88/app.rbl",
            "port": "8090"
        }
    }
}

// Failure response:
{
    "version": "1.0",
    "opt": "otaInform",
    "res": "fail",
    "msg": "ota failed!"
}

Upgrade Progress (downloadProgress)

Actively reports upgrade progress during upgrade, data range 0–100.

{
    "version": "1.0",
    "method": "ota_post",
    "params": {
        "downloadProgress": "0"
    }
}
